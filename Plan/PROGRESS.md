Detection order: valid UTF-8 wins, then the `#ENCODING` header on the first line (key and value case-insensitive, empty value = absent, consulted only when the bytes are not valid UTF-8 - so a pure-ASCII file is UTF-8 even with an odd header), then chardetng. Findings verified against the registry sources: chardetng picks `windows-1250` for realistic Polish/Czech text but `ISO-8859-2` for short lines - user decision: map `ISO-8859-2` to `Windows1250` (same Latin-2 family, the cp1250 table is used either way, round trip stays byte-exact); every other guess errors. | P1-02 | Row classification | done | `rows.rs` with the plan's API (`RowId`, `NoteType`, `NoteRow`, `RowKind`, `Row{id,raw,kind,dirty}`, `Document{file,rows,trailing}`, `classify(DecodedFile) -> Document`); `RowId`'s field is public for tests and consumers (mild deviation from the sketch). `DecodedFileMeta {bom, encoding, encoding_source}` added to `bytes.rs` with `DecodedFile::meta()`. Design decisions derived from the plan itself (no gates): notes without text classify as `Note` with empty text because P1-08 warns about "note with empty text"; an `Invalid` row does NOT start the body (the spec defines body = note/end-of-phrase/voice-change, so a stray junk line does not push the header section away); classification parses the relative-mode second number of `- 10 5` into `rel_offset` and leaves its legality to P1-06 (gate G-01 for semantics) and validation; parse warnings (`P 1`, negative start, unknown note type) are not stored - validation re-derives them from the raw row and row data, mirroring how `Invalid{reason}` is "reported by validation". Whitespace = Unicode `White_Space` without CR/LF per the plan (wider than the ABNF's space/tab; a NBSP-only line is Empty). ABNF facts verified against the spec: header line starts with the hash (`# VIDEO:x` valid, leading space invalid), key `1*header-char` (empty key invalid), value may contain colons (split at first), voice change is exactly one digit then `*WSP` (`P12`/`P 12` invalid; any digit classifies per the plan, P3 flagged by validation), end-of-phrase is `- WSP 1*DIGIT *WSP` plus the relative two-number variant, note type is one visible ASCII char except space and `#` (so `- 10 20 30 la` is a note of unknown type `-`), numbers are `[minus] 1*DIGIT` (a `+` sign or i64 overflow is `Invalid`). 50 tests in `tests/rows.rs`; `scripts/dev.sh check` exit 0. |
