USDX Song Editor

A Kirigami desktop app, written in Rust, for fixing UltraStar Deluxe songs that the USDX Song Factory got almost right: step through the lyric lines, drag notes with the mouse, change pitch, length, type and text, listen at the exact spot, and put racing lines back on time. It reads and writes the format exactly as the spec defines it and changes nothing you did not edit. It is a standalone application: every repair changes the notes in the song file itself, with no Factory, container or network needed. Exporting anchors for the Factory is an extra on top.

Scope

In the first release

  • Open a song .txt with a file dialog, from the command line, or by drag and drop. Recent files appear in the global drawer.
  • A list of lyric lines with start time, type and a timing health dot. A note sheet (piano roll) shows the selected line with its neighbours.
  • Mouse editing: move notes in time and pitch, resize them, select with a rubber band, insert, delete, split, merge, and drag phrase breaks.
  • Note types per line or per note (normal, golden, freestyle, rap, rap golden), with the same keys as the Factory's note_type_editor.py.
  • Text editing per note and per line, with a syllable view that shows how the text maps onto notes.
  • Playback of the full mix, the #VOCALS track or the #INSTRUMENTAL track. Play from the playhead, play the line, play the selection, loop, and play at 0.5x, 0.75x or 1x.
  • Timing repair inside the editor: racing-line detection, anchor + stretch, block move/scale and tap-along. Each one rewrites the start beats and lengths of the notes in the song, and Save writes them to the file.
  • On top of that, an anchors.txt export in the Factory's format, so the corrections made by hand can be fed back to the Factory to develop and test its aligner.
  • Undo and redo for every edit. Saving is lossless, atomic, and writes a backup first.
  • A song properties page for the header tags, a validation list, and the "Upgrade to format 1.1.0" action.

Not in the first release (see open decisions)

  • Editing duets (P1/P2). They load, display and save without loss, but only one voice is editable at a time, and that voice selector comes in a later phase.
  • Video preview with #VIDEOGAP, detected vocal pitch drawn over the notes, and a library browser. Yass has all three, but the job here is fixing one song.

How the UI is used

Four everyday jobs, start to finish.

Fix one line that is a little off

  1. Open the song (Ctrl+O). The line list fills, and lines with suspicious timing get an amber or red dot.
  2. Select the line and press P. The line plays with 0.3 s before and after it. Switch to Vocals (V) to hear only the singer.
  3. Compare the notes with the waveform. Drag-select the whole line (or press Ctrl+A in the line), then drag it or press Ctrl+Right to move it one beat at a time.
  4. Press P again to check. Every move is one undo step.
  5. Save with Ctrl+S. The first save of the session writes .txt.bak.

Repair a racing section

  1. Open Repair timing (Ctrl+R). The overview strip shows red, densely packed lines over a stretch with no vocal activity.
  2. Select the first racing line. Play from a little before it (Space) and press A when the singer starts it. That sets anchor A1.
  3. Do the same for the first correct line after the section (A2). Add more anchors inside long sections when the singing has pauses.
  4. Check the dashed preview, play it at 0.75x, adjust an anchor by dragging its flag, then Apply.
  5. If a few syllables are still off inside a line, use tap-along in syllable mode at 0.5x for that line only.
  6. Save (Ctrl+S). The song is fixed. If you want to give the Factory this case as reference data, Export anchors.txt as well.

Set note types

  1. Step through lines with Down. Autoplay (Shift+A) plays each line as you reach it, as the Factory tool does.
  2. Press F on a spoken intro to make the whole line freestyle, or G to make it golden.
  3. For one note, select it with Left/Right or a click, then press the type key. The line's chip then reads "mixed".
  4. On a rap note the pitch field is greyed out, because the spec says pitch on rap and freestyle notes is ignored.

Correct lyrics and pitches

  1. Double-click a note to fix its syllable in place, or press Ctrl+E to edit the whole line text.
  2. Drag a note up or down to change its pitch (with Shift held, only the pitch changes). Ctrl+Up/Ctrl+Down move it a half step, and with Shift added a whole octave.
  3. Split a long note at the playhead with S, or merge it into the next note with M.
  4. Drag the dashed phrase break to move where the line ends on screen.

Keys and mouse

Type keys match the Factory's note type editor. One difference: Space is play/pause here, as in every media editor, so freestyle on/off moves to F, which toggles. All shortcuts are Kirigami actions, so they show in menus and tooltips.

Architecture

A Cargo workspace. Everything that can be tested without a window lives in plain Rust crates with no Qt dependency, so the TDD loop stays fast (cargo test in seconds). The app crate only translates between QML and that core.

  • Serializer: untouched rows written back verbatim

The note sheet in QML

The sheet is a Flickable holding a Repeater over NotesModel for the visible beat range. Each note is a Rectangle with a DragHandler and two edge handles. A line has 1 to 30 notes, and the window shows about three lines, so the item count stays small. The grid, ruler and waveform are one Rust-painted item behind the notes, which keeps the many thin lines out of the scene graph. During a drag the model only updates a preview. The command is committed on release, which gives one undo step per drag.

Timing repair algorithms

Racing detection

For every line the editor computes three signals and shows the worst one as the health dot:

  • Syllable rate: notes per second of line duration. The default amber threshold is 7/s and red is 10/s, as starting values to tune.
  • Rate against neighbours: the line's rate divided by the median of the 6 lines around it. A factor of 2.5 or more is amber.
  • Vocal coverage: the share of note time during which the #VOCALS track's RMS envelope is above its noise floor. Below 40 % is amber, below 20 % is red. Without a vocals track this signal is off.

Neighbouring red lines are merged into a section. These thresholds are first guesses. They get tuned in phase 7 against songs from the dashboard's "out of sync" reports.

Anchor + stretch

Anchors are (line, true start in ms). Between two neighbouring anchors a and b, every time t in the section maps linearly:

t' = a.new + (t - a.old) * (b.new - a.new) / (b.old - a.old)
beat' = round((t' - GAP) * BPM * 4 / 60000)
length' = max(1, round(length * factor))    // "Scale"; "Keep" leaves lengths alone

Before the first anchor the notes shift by the first anchor's offset, or stay put. After the last anchor they shift by the last offset, or stretch to an optional end pin. A collision pass then walks each voice in order: a note that now starts before the end of the previous one first shortens the previous note (down to 1 beat), then moves forward by one beat. Phrase breaks are placed again at the same relative position in the gap between their two lines. If a beat would become negative, #GAP is lowered first. Tested invariants: start beats never decrease, no overlaps, no break inside a note, all values are whole numbers of 0 or more, and every anchor line starts within half a beat of its pin.

Block move/scale

Block move/scale is a single anchor pair placed at the block's own first and last note: moving shifts both pins, and an edge handle moves one pin. It runs through the same mapping and collision pass. "Move along" adds the end offset to everything after the block.

Tap-along

Playback runs at the chosen rate with a pre-roll. Each key press is stored as pipeline_position - latency, already in audio time, so the playback rate does not need correcting. Line mode turns every tap into an anchor. Syllable mode sets each note start directly and takes the length from the key hold, or from min(old length × local factor, next tap - 1 beat). Latency calibration plays 8 clicks, takes the median of the tap offsets, and stores it in the settings.

anchors.txt export

The export is not how the editor applies its changes. Anchor + stretch, block move/scale and tap-along already rewrite the notes, and Save writes them to the song file. The export is a separate output for developing the Factory: the times a person confirmed by ear, for a song the aligner got wrong, are test cases for the aligner and inputs for its lyrics-mode repair.

This writes the format the Factory reads (docs/repairs.md): a comment header, one m:ss.s | lyric line per anchor in increasing time, and end m:ss.s when an end pin exists. Line text is the joined syllables without ~. The Factory matches anchors from the end of the lyrics, so for a repeated chorus the export warns when an anchored line's text also appears later in the song.

Implementation phases

Every phase runs red, green, refactor: tests first, then the smallest code that passes, then cleanup. The test corpus is handwritten fixtures in the repository, plus an opt-in corpus test that reads every song under USDX_CORPUS=/path/to/library without copying your songs into the repository.

Commands for every note and line operation, an undo stack, and a minimal re-serialization of the rows that changed.

Risks

  • cxx-qt 0.10 is newer than KDE's tutorial (0.8.1). Phase 0 builds the skeleton on 0.10 first and only then writes app code. The fallback is 0.8.1 with the tutorial as it stands.
  • Seek accuracy on opus. Accurate seeks in GStreamer depend on the demuxer. Phase 4 measures this with test files before the sheet depends on it.
  • Lossless and edited at the same time. Edited rows are written in canonical form, and everything else is kept raw. The round-trip corpus test guards against regressions.
  • Detection thresholds. These are guesses until tuned on real broken songs. They are settings, not constants.
  • Wayland key handling during tap-along. Key timestamps come from Qt events and not from the system clock. Calibration absorbs the constant part of the delay.
